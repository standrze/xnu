# Original Apple pthread/platform private Pi build

This is an offline build result, not a new Pi runtime. The accepted startup,
kernel, RAM root, VM sources, and existing crypto artifacts are unchanged.

## Source and build evidence

The target package is `build/rpi5/apple-pthread-platform-linkable-ydcl_6yv`.
Its manifest SHA256 is
`c31e25c5c81d14423d3204f6e9f215f2a15f6da35b63d4dd7b378d8bce45138c`.
The partial archive SHA256 is
`65093cd32a2af95982f02abb4219bc1436262be9d0f85fa04bdd187b2bb58cab`.

The pristine Apple source revisions are recorded in that manifest, including
libpthread `42d026df5b07825070f60134b980a1ec2552dfee` and libplatform
`2512ffd8bb5c6caff3c8ea83331ab8a0adc820c3`. Original implementation files were
compiled directly; they were not rewritten. Each successful compilation has
both a before-build dependency scan and an actual compiler `.d` file, and those
exact dependency sets and hashes agree. Failed compilation retains the missing
header inventory, actual include trace, and complete diagnostics.

Fourteen of fifteen selected Cortex-A76 translation units compile. They include
the original pthread mutex, condition, rwlock, TSD, cancellation, atfork, cwd,
and QoS units, and platform lock/once, atomic, semaphore, alloc-once, and getenv
units, plus the original libsyscall alloc-once table. This is not an inventory of
every source file required for a complete Apple libSystem.

Private-header installation copies original Apple headers byte-for-byte.
Availability headers are produced by Apple's actual AvailabilityVersions
generator. The original optional `--av_version` path has an upstream list/string
error; the build uses its unchanged `Local` default and pins the actual revision
and generated bytes independently. The compilation-only forced header adds a
declaration of the real `_os_xbs_chrooted` import and maps the old xros availability
spelling to visionos, following Apple's own platform alias. No behavior/provider
is manufactured. The JIT-write-protection source remains enabled. Platform
`CONFIG_MTE=1` is retained from the upstream macOS arm64 configuration.

## Remaining main pthread compilation boundary

`src/pthread.c` does not compile. Its concrete remaining prerequisites are:

1. The published `libsyscall/os/thread_self_restrict.h` contains an empty guard,
   not declarations or implementations of `os_thread_self_restrict_rwx_is_supported`,
   `os_thread_self_restrict_rwx_to_rx`, or `os_thread_self_restrict_rwx_to_rw`.
   The original pthread JIT-protection paths call these services. Disabling those
   paths or declaring success-returning substitutes would change the security
   contract; neither was done.
2. The pinned current public dyld header uses `DYLD_EXCLAVEKIT_UNAVAILABLE`
   without defining it. The installed public SDK header has a definition, but
   the private build did not silently splice different dyld header versions.
3. The workloop callback needs the genuine `kqueue_id_t` declaration from
   `bsd/sys/event_private.h`, not the public SDK event header currently selected.
   This header-installation detail is small, but does not resolve item 1.

## Original platform native tests

The separate validation package is
`build/rpi5/apple-pthread-platform-check-m7im0unk`, manifest SHA256
`463cdcb6bd64b4cecb756ed1886288bb81b116a1ab3592ffa987a67dc0c2d6dd`.
It recompiles the exact original platform lock/once, atomic, and semaphore sources
with AddressSanitizer and UndefinedBehaviorSanitizer. Definition names alone are
prefixed in this host test, preventing accidental interposition of macOS's own
libSystem. The target archive is not renamed or modified.

Eight actual macOS pthreads perform 160,000 protected increments, 160,000 original
Apple atomic increments, one contended initializer with published state, and
eight semaphore signal/waits. A held-by-another-thread trylock fails correctly;
invalid wait/wake sizes return EINVAL. The original implementations use actual
host TSD, ulock, commpage, and Mach services, not test substitutes. These tests
exercise the original platform primitives, **not** the newly compiled target
pthread implementation or Pi kernel services.

## Real static packet link

Appending the partial archive to the preserved original Apple packet/LibreSSL/
sysctl link resolves the previous mutex and pthread-self implementations. It
exposes these eight real unresolved symbols:

| Required symbol | Source-side role |
| --- | --- |
| `__psynch_mutexwait`, `__psynch_mutexdrop` | Original pthread fairshare/firstfit blocking paths |
| `__ulock_wait`, `__ulock_wait2`, `__ulock_wake` | Original pthread/platform blocking and wake paths |
| `_pthread_ptr_munge_token` | Main initialization/signature validation state |
| `abort_with_reason` | Genuine invalid-pthread-signature failure path |
| `pthread_equal` | Main pthread unit; LibreSSL error-state ownership comparison |

The Mach-O linker adds an additional leading underscore to these C names. There
were no duplicate-symbol diagnostics in this narrow dead-stripped link, but that
does not make the accepted process-local key map compatible with real pthread
TSD. The link still fails and no runnable packet executable is produced.

The next implementation slice must preserve original syscall errno/NO_ERRNO
semantics and genuine abort behavior, then establish the full main-thread
initialization contract: struct pthread layout/signature, token, TSD, thread
port/id, stack and scheduler metadata, bsdthread registration, and real startup
ordering before constructors. Merely defining a token or borrowing the bootstrap
128-word TSD would be invalid. A future full runtime must also replace the old
key-map provider in a distinct startup artifact, never silently override it.
